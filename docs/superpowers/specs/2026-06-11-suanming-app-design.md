# 算命应用设计文档

日期：2026-06-11
状态：已确认

## 1. 产品概述

一个面向中文用户的命理 Web 应用：用户输入生辰，系统用开源库确定性排出八字盘和紫微斗数盘，再由豆包大模型基于完整命盘数据生成结构化解读报告，并支持后续对话追问。带邮箱密码账号体系，可保存多个命盘和历史解读。

**核心价值主张**（区别于直接问通用聊天机器人）：

1. 排盘由代码保证百分之百准确——大模型做历法推算不可靠，本应用只让模型做它擅长的解读。
2. 喂给模型的是完整结构化命盘（十神、藏干、大运流年、紫微十二宫四化），信息密度远超用户手打一句生日。
3. 产品化体验：盘面可视化、结构化报告、命盘保存与历史记录。

## 2. 范围

### 第一版（本设计）

- 八字 + 紫微斗数排盘与盘面展示
- 豆包生成解读报告（流式输出）
- 报告后的对话追问（流式，按命盘保存对话）
- 邮箱 + 密码注册登录
- 命盘列表 / 历史解读查看 / 删除命盘
- 响应式（移动端优先），国风视觉
- 每用户每日 LLM 调用上限（默认 20 次，环境变量可调）

### 明确不做（后续版本）

- 微信 / 手机号登录、付费、合盘、流年订阅推送、小程序壳

## 3. 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 框架 | Next.js 15（App Router）+ TypeScript | 单体全栈，前后端一个代码库 |
| 样式 | Tailwind CSS | 响应式开发效率 |
| 数据库 | SQLite + Drizzle ORM | 单文件零运维，体量足够 |
| 认证 | better-auth（邮箱密码） | 现成的会话与密码管理 |
| 八字排盘 | `lunar-typescript`（6tail） | 事实标准库，干支/节气/神煞/大运全覆盖 |
| 紫微排盘 | `iztro` | 事实标准库，安星/十二宫/四化全覆盖 |
| 大模型 | 豆包（火山方舟 Ark API，OpenAI 兼容格式） | 用户已有火山引擎账号；SSE 流式 |
| 部署 | Docker，目标国内 VPS | 第一版先本地跑通，部署细节实现阶段定 |

**排盘零自研**：排盘算法完全由上述两个开源库承担。自研部分仅为薄胶水层——输入适配（公历/农历、闰月、真太阳时经度校正）和输出拼装（统一命盘 JSON）。

## 4. 架构

三层结构：

```
[页面/组件]  →  [API 路由]  →  [排盘胶水层 → lunar-typescript / iztro]
                    ↓                ↓
              [Drizzle/SQLite]   [豆包 Ark API（仅服务端，ARK_API_KEY 环境变量）]
```

- **排盘胶水层**：纯函数，无 IO，可独立单元测试。输入生辰参数，输出统一命盘 JSON。
- **API 层**：命盘 CRUD、报告生成（SSE）、追问对话（SSE）。所有 LLM 调用在服务端，密钥不下发前端。
- **数据层**：命盘排好后存 JSON 快照，解读与追问均读快照，不重复计算。

## 5. 排盘胶水层

**输入**：姓名、性别、历法类型（公历/农历）、出生日期、时辰、是否闰月（农历时）、出生地（可选，省市下拉，内置静态省市→经度表，用于真太阳时校正；不选则按北京时间）。

**输出**：

- **八字盘 JSON**：四柱干支、各柱十神、藏干（含藏干十神）、五行旺衰统计、神煞、起运岁数与方向、十步大运（每运干支与十神）、当前所处大运、当前流年流月干支。
- **紫微盘 JSON**：十二宫（宫名、地支、主星辅星杂曜及亮度）、命宫身宫位置、五行局、生年四化、当前大限与流年位置。

**边界处理**：农历闰月、子时跨日（晚子时归次日）、节气交界日的月柱归属、真太阳时校正后跨时辰/跨日——这些由库处理，胶水层负责把参数传对，并用单元测试锁定。

## 6. 大模型解读

### 报告生成

- **System prompt**：资深命理师人设；固定解读框架——命局总评 / 性格特质 / 事业财运 / 婚恋情感 / 健康提示 / 近三年大运流年；语气要求客观、建设性，不做宿命论恐吓，不预言具体灾祸死亡；结尾固定免责声明（仅供参考娱乐）。
- **User content**：命盘 JSON 渲染成结构化中文文本（非裸 JSON），八字紫微两盘齐喂。
- **输出**：Markdown，SSE 流式打字机展示，完整生成后存入 `readings`。流中断不存残缺内容。
- **重新生成**：允许重新生成报告，每次追加一条 `readings` 记录；命盘页只展示最新一份。

### 追问对话

- 每个命盘一条对话线，消息持久化，可回访继续。
- 上下文组装：system prompt + 命盘文本 + 最新一份报告全文（若有）+ 历史消息。
- 同样 SSE 流式；上下文过长时从最早消息截断（命盘与报告始终保留）。

### 成本保护

每用户每日 LLM 调用次数上限（报告 + 追问合并计数），默认 20，环境变量 `DAILY_LLM_LIMIT` 可调。超限返回友好提示。

## 7. 数据模型

| 表 | 字段 |
|---|---|
| better-auth 系列 | `user` / `session` / `account` / `verification`，由库管理 |
| `charts` | id、userId、name、gender、calendarType、birthDate、birthTime、isLeapMonth、birthPlace（可空）、baziData(JSON)、ziweiData(JSON)、createdAt |
| `readings` | id、chartId、content(Markdown)、model、createdAt |
| `messages` | id、chartId、role(user/assistant)、content、createdAt |

级联：删除命盘时连带删除其 readings 与 messages。

## 8. API 路由

| 路由 | 说明 |
|---|---|
| `/api/auth/*` | better-auth 托管 |
| `POST /api/charts` | 创建命盘（排盘 + 存快照） |
| `GET /api/charts` | 当前用户命盘列表 |
| `GET /api/charts/:id` | 命盘详情（含报告与消息） |
| `DELETE /api/charts/:id` | 删除命盘 |
| `POST /api/charts/:id/report` | 生成解读报告，SSE 流式 |
| `POST /api/charts/:id/chat` | 追问对话，SSE 流式 |

所有命盘路由校验登录态与资源归属（只能访问自己的命盘）。

## 9. 页面

| 路由 | 内容 |
|---|---|
| `/` | 落地页：产品介绍 + 排盘入口（未登录可浏览，操作需登录） |
| `/login` `/register` | 邮箱密码 |
| `/charts` | 我的命盘列表（卡片：姓名、生辰、创建时间） |
| `/charts/new` | 排盘表单 |
| `/charts/[id]` | 核心页，自上而下：盘面可视化（八字四柱表 + 紫微十二宫格，移动端自适应堆叠）→ 解读报告（无报告时显示"生成解读"按钮）→ 追问对话框 |

视觉：国风（墨色/暗金系方向），移动端优先；具体视觉语言在实现阶段用前端设计流程细化。

## 10. 错误处理

- 豆包调用失败/超时：前端展示错误与重试按钮；SSE 中断丢弃残缺内容不入库。
- 排盘输入校验：非法日期、农历无此闰月等在表单层与 API 层双重校验。
- 超出每日调用上限：明确提示剩余配额恢复时间。
- 未登录访问受保护路由：跳转登录页。

## 11. 测试策略

- **排盘胶水层单元测试（重点）**：用若干已知正确答案的生辰核对输出——普通用例、农历闰月、子时跨日、节气交界日、真太阳时校正跨时辰。正确答案以权威排盘工具人工核对后写死在测试里。
- **API 集成测试**：认证、归属校验、CRUD、配额限制；LLM 调用 mock。
- **LLM 层**：prompt 组装函数单元测试（命盘文本渲染、上下文截断逻辑）；不测真实模型输出。
